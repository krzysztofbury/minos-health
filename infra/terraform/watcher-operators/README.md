# Watcher IAM Operator Bootstrap

This root owns the fixed IAM permission ceilings, three operator roles, and
their identity policies. It does not create the snapshot bucket, watcher access
key, application runtime, or any disposable acceptance resource. Its Terraform
state is kept in the existing versioned bootstrap bucket at
`watcher-operators/terraform.tfstate`, separate from watcher production state.

The only bootstrap caller is the existing `minos-health-bootstrap` SSO profile,
resolved through STS to the pinned `MinosAdministrator` Identity Center role in
account `218375352108`. That broad profile is for this reviewed one-time IAM
bootstrap only. Normal watcher Terraform plans and applies use the separately
assumable scoped production operator after these resources exist.

## Identities

- `minos-health-watcher-terraform-operator`: manages only reviewed Minos
  watcher state, bucket controls, IAM user/policy, GitHub archive reader, budget,
  and SNS resources. Its own boundary and identity policy are the same scoped
  document. It cannot create an access key or pass a role.
- `minos-health-watcher-acceptance-operator`: manages only disposable
  `minos-health-watcher-acceptance-*` buckets and roles, with a fixed
  `iam:PermissionsBoundary` condition and required request tags. It has no
  Terraform production-state or IAM user access.
- `minos-health-watcher-state-recovery`: independently assumable access to
  versions of the two exact watcher state keys, conditional restoration, and
  inspection/removal of only their lock objects. It cannot delete state versions.
- Three separate, fixed managed boundaries cap the Mikr.us watcher IAM user,
  GitHub archive reader role, and disposable acceptance watcher role to their
  reviewed S3 paths and verbs. None grants general IAM, deletion of raw bytes,
  or a write path for the GitHub reader.

Each role trusts only the reviewed SSO role ARN via `aws:PrincipalArn`. Every
role also carries its own fixed permission boundary. A role session receives
the intersection of its identity policy, boundary, resource policies, and any
organization controls. AWS IAM policies themselves have no direct hourly charge.

## Review-only plan

From the repository root, authenticate the pinned SSO profile and verify the
account before planning:

```sh
cd ~/Work/minos-health
mise exec -- aws sso login --profile minos-health-bootstrap
mise exec -- aws sts get-caller-identity --profile minos-health-bootstrap
AWS_PROFILE=minos-health-bootstrap \
  mise exec -- scripts/aws-watcher-operators-apply.sh
```

The script verifies the STS principal, state-bucket owner/region, backend account,
complete 13-resource create-only plan, fixed role trust, boundary names and
policies, and 23 bounded read-only IAM simulator allow/deny decisions. It writes
a mode-`0400` saved plan and mode-`0600` JSON under the
ignored `artifacts/aws-watcher-operators/` directory. Review those bytes and
the printed SHA-256 before any apply. A plan made with any changed principal,
code, inputs, or saved state must be regenerated and approved again.

Apply requires a separate exact confirmation supplied to the same script:

```text
MINOS_AWS_OPERATORS_APPLY_CONFIRM=APPLY-OPERATORS:218375352108:<reviewed-plan-sha256>
```

Do not run it merely because a sample confirmation exists in documentation.
Only the operator who reviewed the exact plan may provide the matching digest.
No watcher AWS key is generated by this root or saved in Terraform state.
Immediately before apply, the script also checks that the three named roles, six
named boundary policies, and operator state object are still absent in AWS. It
compares the saved plan through one open descriptor before applying that same
descriptor. Any preexisting identity, unreadable target, or mismatched plan
stops the apply instead of adopting an unmanaged IAM principal.

After an approved apply, confirm the three exact role ARNs and boundaries via
AWS, then use live-role IAM policy simulation and explicit denied-action probes before
running disposable acceptance or applying the production watcher root. Store
only non-secret profile references and recovery instructions in 1Password; do
not put SSO sessions or credentials into Terraform inputs, Git, or images.

Add three local AWS CLI profiles that assume these roles from the existing SSO
bootstrap session. For example, the non-secret production profile is:

```ini
[profile minos-health-watcher-operator]
role_arn = arn:aws:iam::218375352108:role/minos-health-watcher-terraform-operator
source_profile = minos-health-bootstrap
region = eu-central-1
```

The acceptance and recovery profiles use the exact role ARNs returned by this
root. Verify each profile with `aws sts get-caller-identity`, then check allowed
and denied operations with the IAM simulator. Keep the broad SSO profile for
break-glass bootstrap only; production plans and applies must reject it.

The production watcher IAM user and GitHub reader role in
`infra/terraform/watcher/iam.tf` must retain the boundary ARNs created here.
Regenerate that root's saved plan under the scoped operator profile and obtain a
second independent digest-specific approval before applying it. The older
bootstrap-administrator plan is review evidence, not an apply candidate.
